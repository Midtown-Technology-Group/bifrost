## Observation and transport

CapturedStep contains the unchanged W0 Observation plus separate
TransportEvidence(sdk_requests,model_requests,vendor_requests). HTTP status,
body, committed database rows and ordered Redis publications are independent.
The SDK plane records real requests forwarded by an owned test-only observer
to the real API. It is not a database row, event, copied SDK object or live
vendor proof. Model/vendor lists must be empty in A.

The observer verifies the engine JWT signature, issuer, audience and type,
then checks its original caller/org against the independently registered
execution owner. It retains credential scheme/presence and verified claims,
never the bearer JWT or raw attempt token. A token digest must match a
committed workflow-attempt fence for the same signed execution before comparison.
Its comparison alias includes the execution role and attempt number. Owned SDK
requests must match the approved POST endpoint, empty query and exact synthetic
name/scope/body before forwarding or retention; rejection messages contain no
request bytes. Only the fixed synthetic
config value may be retained; unexpected credentials/configuration refuse
capture. Network-path and absolute request paths are refused; constructed
upstream authority is fixed to http://api:8000, with redirects disabled.

Fresh SQL snapshots cover all columns of owned execution, workflow attempt,
generic attempt, lifecycle event, delivery, log, audit, agent/step and usage
rows. The encrypted delivery envelope is replaced by its actual decrypted
synthetic semantics plus encrypted-presence evidence; an unexpected engine
credential stops capture. Terminal DB and real terminal history-publication
barriers precede the final capture. Redis observes all channels but attributes
only explicit owned IDs; a scope-preserving wrong-channel publication is
observable. Events that lose every scoped identity cannot be attributed safely
in shared Redis and remain an acceptance limitation.

The explicit Core profile leaves the device default unchanged. It maps only
declared column/protocol/source-local identity paths. Generated row/fence/worker
IDs retain same-run equality and wire type. Original caller/org/workflow IDs
must use seeded bindings; arbitrary unexpected IDs are not autogenerated roles.
Only declared readiness locals and input identities have source-specific mappings;
input-derived locals must agree with the execution parameters. The complete raw
25-key pending context is bound to the same execution/delivery, hash-bound dispatch,
caller, scope and producer schema before seven exact identity leaves and one
producer clock can be projected. The public producer omits optional file_path
and identifies the source through dispatch_metadata.path. Known foreign fixture
substitutions and bool/int laundering are rejected. Logs, other variables, script text, result
numbers and other nested payload remain opaque. Installed
execution_context.workspace_generation has one explicit binding, tied to
verified source readback and the observed Redis generation.

Declared server clocks must occur inside measured observation windows; aliases
preserve order/equality/nullability. Raw evidence remains intact. Runtime
duration_ms is an integer in milliseconds, bounded by the measured operation
and checked against HTTP/event/attempt projections. Exact DB CPU fields are
finite nonnegative float seconds; total must equal user+system within 0.0002
because the worker rounds to four decimals. Cumulative process CPU is not
bounded by wall elapsed time. Exact memory fields are integer bytes within
PostgreSQL's signed-bigint range. Accepted workflow attempts must agree with
the same-run execution's duration, peak memory and total CPU. Presence, type,
units and these relationships compare across processes; raw magnitudes are
retained in the report. No applicable finite runtime cgroup measurement is
provided in R0; its additional cgroup upper-bound gate remains pending.

Dispatch hashes are validated against their raw semantic documents before
identity-derived hashes receive a comparison marker. Workflow attempt hashes
must agree with the same-run execution. Runtime mode/evidence/hash remain
captured and meaningful. The fresh editor/register installation commonly uses
unfenced repo-v1; that is useful Python characterization but **cannot satisfy
the final A ownership gate**, which requires an existing supported pinned
Solution deployment or workspace release.
