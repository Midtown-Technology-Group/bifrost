## Actual reference and comparison

One supported API pytest process owns the cohort. For each shared input case it commits legal current-schema PostgreSQL rows, independently reads actual execution/attempt/history facts, invokes the compiled Rust kernel driver with those facts, executes the real Python operation, then independently reads committed effects. The manifest contains raw arrangements and inputs, never expected accepted booleans or final rows. The reference methods are `mark_attempt_running`, full `WorkflowExecutionConsumer._process_success` / `_process_failure`, and `ExecutionRepository.cancel_execution`. No mock admission, finalizer, classifier, repository or expected-result adapter substitutes for those methods.

The comparison checks every selected directive and unchanged unlisted columns. Keep preserves existing values; SetSupplied includes real SQLNULL; Now is tested against legitimate operation windows and source-specific sampling order. Optional projection eligibility is distinct from an actual supplied value. A scoped observer may capture the consumer's actual supplied arguments only while forwarding the retained original unchanged and restoring it in failure-safe cleanup. Actual repository JSON, result-type and Teams conversion remain Python-owned; this kernel is not their Rust implementation.

Cases must cover all10 recognized success statuses (including incumbent nonterminal projections), four error families, all prior-Cancelling overrides, missing/stale/foreign/completed fences, claimed-without-start finalization, None/omitted/empty/zero inputs, non-NULL sentinels, legal attempt history, and actual cancellation-first/result-first committed ordering. Impossible SQL shapes remain labeled synthetic unit coverage, not differential evidence. Running coordinator loss is outside the combined plan; legacy unfenced handling is outside the tracked path. Neither is falsely characterized as Python denial. Fixture omission, illegal seeding or unknown output fails rather than being skipped or redefined.

Drift controls must demonstrate detection of changed acceptance, directives, preserved sentinels and fencing/cancellation decisions against actual reference effects. A manipulated retained-plan comparator test is a detector test, not another backend execution. Python event observations use real effects where captured; candidate event parity is **not applicable** because the kernel emits no events. Absent buffered-log/payload/event adapters remain explicit gaps. Full mixed-writer and HTTP/domain-owner tests remain separate.

## Closed test interface

`bifrost.test.workflow-domain/v1` is a dev-only request/response schema, not a runtime P0 or public SDK contract. One bounded UTF-8 JSON request/response runs per subprocess. Case labels are ASCII `[A-Za-z][A-Za-z0-9_-]*`, length1..64, verified against the closed manifest. Input is at most65,536 bytes, output at most4,096. The Python conductor bounds output allocation during reads, enforces deadlines and kills/reaps failure; no Rust watchdog framework is introduced. Unknown fields, invalid enums/UUIDs, arrays in object positions, numeric enum coercions, duplicate fields and extra JSON fail with fixed non-sensitive diagnostics. Structural checks use existing `serde_json`, followed by closed DTO parsing of the original bytes so duplicate rejection is preserved.

Requests contain `schema`, `case_id`, tagged `operation` and factual `rows`. Rows contain required nullable `execution`, `attempt`, and actual `history`. Attempt fields are its existing IDs/token/status/phase and timestamp-presence facts. Tokens are synthetic fixture inputs, immediately wrapped in the production opaque capability and never returned or logged. Only process/duration inputs may be omitted; missing nullable row/token fields cannot silently become invented facts. Logical strings use the exact stored Python vocabulary and attempt strings the existing lowercase vocabulary.

Operations are running (execution, token, optional process), result (execution, nullable token, success/failure/coordinator input and resolved optional duration), and cancel (execution). Actual consumer default duration0 differs from explicit None: send the resolved argument, not a guessed omission flag. Responses contain case/schema and accepted tagged plans or existing static rejection labels; running/cancel plans are flat and result plans contain execution/attempt subobjects. Every field comes from the actual kernel. Python false does not prove one precise Rust rejection reason. Production capability/view types gain no serialization or getter.

## Supported custody and commands

The existing pinned checks image runs `cargo fmt --check`, `cargo clippy --locked --all-targets --all-features -- -D warnings` and `cargo test --locked --all`. The driver additionally runs `cargo test --locked --offline -p bifrost-domain --example workflow_domain_vectors` and a locked/offline example build. Default workspace tests alone do not certify execution of the example's own tests.

The actual binary is copied through the existing `LOG_DIR` mount to `/tmp/bifrost/workflow-domain-parity/driver`; ABI is exercised inside the actual supported API test image. Its `receipt.json` has schema `bifrost.test.workflow-domain-receipt/v1`, candidate SHA/tree, binary SHA256, fixture SHA256 and15 source hashes. Python checks actual binary/fixture and accessible mounted Python files; it cannot claim to re-read absent Rust files inside API. The source/build producer binds those files. No DB/Redis/registry/Git credentials are forwarded to the driver subprocess.

The clean committed candidate must contain current main and pass literal `./test.sh pre-pr`. The gate then invokes unchanged `./test.sh tests/parity/test_workflow_domain.py -v` once. The dedicated workflow's private-branch push permits supported pre-publication evidence; normal PR/manual gates remain. No host product/runtime tests occur on pve-t340.

Before claiming runner image custody, retain and compare the shared image identity before and after `test.sh`'s possible rebuild; a mismatch fails. Remove earlier JUnit before the targeted invocation and retain its fresh record. Every cleanup inspection and receipt write must be checked; missing output cannot accompany successful acceptance. Verify the task-owned project's containers/volumes/networks after teardown rather than equating a down command with EMPTY. Preserve original failure status and fail prior success on custody/disposal errors. Source-level tests or echo receipts cannot replace actual supported evidence.
