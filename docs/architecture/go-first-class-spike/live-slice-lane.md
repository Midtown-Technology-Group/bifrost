fresh migrated task database. The authenticated API test process creates one

never receives `wex_core`. Common mechanical guards deny incumbent writes to the
Rust-owned lifecycle. No role grants or credentials change. The tenant never sees
any database, Redis, Docker, signing, caller-authentication or issuer authority.

original UID/PID/start-ticks and authenticate private Unix IPC; it receives the
same task-owned result directory at its host pathname. Rust sets non-dumpable
process protection before handling config/credentials, and the fixture requires

fixture boundary requiring security review before acceptance. It is not a tenant
namespace policy or a production Compose change. The API test runner receives no
Docker socket. The host launcher uses UID1000 and the existing Docker group only
for the Rust guardian's already-authorized physical custody. The tenant carrier
continues with private PID/network namespaces, read-only mounts and dropped caps.

The fixture starts the single-route restricted TLS server with IP SAN127.0.0.1
before original guardian creation. It derives finite provision preimages from
actual committed Start/caller rows, then starts the actual finite one-use issuer.
Rust commits provision/release, delivers actual issued material through the original
private FIFO, services SDK admission and accepts exact Result bytes. A Receipt goes
out only after observed commit. The fixture observes original owner exit before
using the existing authenticated Execution API to read the actual durable result.
A second execution uses the same archive and binary with fresh identities, no build.

Normal success requires SDK HTTP200, one SDK admission, the fixed common LogBatch,
Result/Receipt byte-hash agreement, public Success/result readback, original
container/namespace drain and staging/issuer/socket/key cleanup. The shell driver
never replays a transaction, material delivery or launch. Uncertain failures retain
the original config/journal and permit only `runtime-live-owner --drain` with that
same spec/nonce. A residue fails cleanup; no new owner or launch is created.

Evidence retention is an explicit public allowlist, excluding private delivery,
issuer material and TLS keys. Owner metadata removes the private claim token;
raw execution config remains private and is never uploaded. Broad unit/API quality checks remain required. Actual
writer-guard/security/race evidence must qualify the same source before acceptance.

Remaining gates: live crash/unknown commit/spawn/lost-ACK cases and human
acceptance of the reviewed writer/runtime evidence. Durable cancellation and
source-consumer settlement now have source-bound live proof below. A physical
drain or successful conformance run alone does not satisfy these gates.
