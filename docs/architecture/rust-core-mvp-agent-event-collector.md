Selected channels are actual pattern bifrost:agent-run:* and exact bifrost:agent-runs:all plus bifrost:agent-runs:org:<org UUID>. None are aliases/global fallbacks.
2. Retain every actual selected-channel business publication, including genuine channel fanout duplicates. Exactly one shared64 budget pre/post-bind, each raw data at most65536 UTF8 bytes, aggregate at most4194304. No eviction, dedup, discard, silent reset, wrap or resumed failed collector. Validate raw bounds before JSON parse/retention; this is not a guarantee about Redis client's allocator. Unknown channel/type/pattern/malformed body is permanent failure.
3. Event data must be bytes (actual connection configured decode_responses=False; a string is not original byte evidence). Decode strict UTF8/JSON, reject duplicate object keys, nonfinite numbers, non-object top level; catch parser errors without retaining message/exception. The immutable record holds original raw bytes privately (repr=False), channel, pattern identity or null, actual collector time.monotonic_ns string and collector-local one-based index. Do not claim this clock orders commits or clocks from other processes. Snapshot APIs must not expose mutable internal state. Stored raw bytes remain internal; no stdout/artifact/log/hash export.
4. Accept only current agent_run_update and agent_run_step source types and actual canonical run_id. Updates require matching actual Agent ID/org ID and matching channel association. Steps require actual detail channel and step object; their source payload does not contain Agent/org, so do not invent those fields. Step identity is checked against binding later and actual committed reader separately. Retain full original object/bytes; never remove unknown fields to make equality pass. Finite JSON depth64/node8192 guard is collector admission policy; overflow fails, it is not a public event schema rewrite.
5. Maintain real publication order and duplicate channel identity; pre-persistence step events are not committed row evidence.

## Subscription acknowledgement interface

The concrete async Redis adapter is deferred until independently reviewed. The collector exposes explicit acknowledgement handling for only the three selected subscription identities: psubscribe on pattern and subscribe on each exact channel. Retain each once, require Redis integer subscription count1,2,3 in actual arrival order (bool/string invalid), reject duplicate/malformed/unknown ACKs. Unknown Redis message types fail; no ignore_subscribe_messages=True readiness inference. Business publications may interleave and consume the same64 budget. Readiness becomes true only after all three genuine ACKs; arm/enqueue must require readiness. ACK messages are not business receipts and grant no extra business capacity. Max3 ACKs, each fixed selected identity<=128bytes; separate total control count3, no optional ping or resubscribe fallback. One actual monotonic3-second readiness deadline belongs to the future adapter, starts before subscribing; no retries. Collector's pure unit API receives genuine message mappings, and cannot itself prove subscription I/O.

## Lifecycle and error surface

First failure latches a closed static code (invalid_state, identity_mismatch, invalid_message, invalid_payload, capacity_exhausted, acknowledgement_mismatch). All subsequent mutation/admission/bind calls reject; failed object cannot be reused. close only prevents further admission; it is not producer/Redis quiescence or domain settlement. Accepted snapshot is available only with ready+bound+not failed; premature snapshot fails. Producer closure/drain/subscription cancellation and exact ACK deadline enforcement are separate integration interfaces; no nominal success from local close(). No automatic retry. Fixed errors contain no payload, customer script, credential, raw ID or exception string.
