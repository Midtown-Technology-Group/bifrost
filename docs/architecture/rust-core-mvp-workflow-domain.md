## Exact data and signatures
Use existing CanonicalUuid for public IDs. ClaimToken is a private-representation wrapper around that validated UUID, with constructor new(CanonicalUuid), equality/Clone only. No Debug,Display,serde,as_str or secret-bearing rejection/plan; no derived Debug/serde on containing views. No raw result/log/error/variables/customer payloads.

LogicalExecutionView contains actual stored id and logical status. WorkflowAttemptView contains actual stored id, execution_id, nullable ClaimToken, attempt status, phase, started_at_present and completed_at_present. Presence fields are facts from actual columns, not authorization flags. process_id_supplied is true iff the actual process_id argument is non-None (empty string counts); duration_supplied is true iff actual logical duration argument is non-None (zero counts). Omitted/explicit None are false. AttemptHistory is Recorded/Unrecorded from the actual caller query; it is not owner/caller admission. All inputs are ordinary trusted parent row facts; kernel has no authorized/source_ok/session_live flags.

Public signatures (type names frozen; lifetimes/borrowing may be idiomatic):
- plan_attempt_running(attempt: Option<&WorkflowAttemptView>, execution_id: &CanonicalUuid, token: &ClaimToken, process_id_supplied: bool) -> Result<AttemptRunningPlan,DecisionError>.
- plan_fenced_result(execution: Option<&LogicalExecutionView>, attempt: Option<&WorkflowAttemptView>, execution_id: &CanonicalUuid, token: Option<&ClaimToken>, history: AttemptHistory, outcome: WorkflowOutcome, duration_supplied: bool) -> Result<FencedResultPlan,DecisionError>.
- plan_cancel_state(execution: Option<&LogicalExecutionView>, active_attempt: Option<&WorkflowAttemptView>, execution_id: &CanonicalUuid) -> Result<CancelPlan,DecisionError>.

WorkflowOutcome: Success(LogicalExecutionStatus), Failure(RuntimeFailureKind), CoordinatorLoss. RuntimeFailureKind: Timeout,Cancelled,ResultPersistence,TenantCode. Success input is already normalized by the trusted parent, preserves ALL TEN logical statuses. Unknown-string->Success normalization remains future adapter behavior, not kernel parsing. Do not narrow success to terminal values: current consumer can write a recognized nonterminal logical status while attempt succeeds. Record this awkward compatibility behavior as future cleanup, not a port correction. CoordinatorLoss is a parent's classification, never arbitrary child-selected text; its running logical projection/retry is excluded below, without claiming Python rejects it.

Field directives must distinguish Keep from writing SQL NULL. Use TimeWrite::{Keep,Now}; InputWrite::{Keep,SetSupplied} for optional input columns (SetSupplied includes a NULL input); and typed status/phase/failure-code fields. No metrics values/payload serialization belong here. Immutable plain row plans describe only columns below; they carry no secret, authority permit, transaction proof or committed Start.

## Running exact table
Reject absent attempt, wrong execution_id, absent/wrong stored token, completed_at present, or status outside claimed/running. Do not inspect logical execution status, heartbeat/session, started age or worker ID. Matched incomplete claimed/running: attempt.status=running; phase=execution; heartbeat_at=Now; started_at=Keep if present otherwise Now; process_id=SetSupplied ONLY when process_id_supplied else Keep. All other columns Keep. This is mark_attempt_running behavior; only future SQL commit makes it durable. Never turn this plan into P0 StartAuthorization.

## Tracked result exact table and precedence
FIRST if submitted token absent: Recorded history -> MissingFence; Unrecorded -> LegacyUnfencedOutsideTrackedPath, no row plan. Neither classification applies the fenced logical guard to legacy. Python actually has an unfenced legacy projection; retaining it is future adapter/strangler responsibility, not a rejection claim. Factual history/selected rows come from one transaction.
With a submitted token, require present logical row with matching execution_id and status Running/Cancelling. Require matched attempt.execution_id/stored token, completed_at absent. NO claimed/running attempt.status guard: finalize_attempt does not impose one. Valid DB active shape limits actual reachable tuples; kernel must not invent a stronger predicate. Other mismatches reject with no plan/effects. Error variants are internal, not public HTTP error contracts.

Preserve started_at and other identity/pin fields. Variables/context/metrics/logs remain eligible for adapter projection EVEN WHEN cancellation wins; source-compatible Teams context merge/log sequencing/JSON behavior remains adapter-owned.
