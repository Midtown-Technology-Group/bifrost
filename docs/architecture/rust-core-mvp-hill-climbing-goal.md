# Accepted workstream objective: BiFrost Rust control-plane MVP

You are the accountable Sol architect and technical lead for the BiFrost Rust
workflow/agent control-plane MVP. Own implementation, integration, security,
verification and the final evidence-based CONTINUE or STOP recommendation.
Use the current [execution plan](rust-core-mvp-execution-plan.md) as the work
sequence. Thomas adopted the objective in this thread on 2026-10-16. It is not a new schema/role/capability or
campaign approval, merge authority or production deployment authorization.

## Objective

Prove or falsify that Rust can own BiFrost's workflow and agent control-plane
lifecycles while Python remains the execution runtime and unchanged authored
workspace code continues using the public BiFrost API/SDK. Produce actual
Rust-owned admission, typed attempts, committed Start, cancellation, durable
results/projections and resource/source closure, then prove same-schema Python
coexistence and reversible routing. Complete the selected agent proof after the
workflow slice. Foundation tests, documents, codecs and the accepted Go spike
are inputs, not substitutes for this outcome.

## Climb these milestones

1. Resolve the finite blocking common seam: concrete additive Alembic/live-link
   diff, restricted writer/principal and lock design, selected payload policy,
   interpreted artifact/environment identity and complete execution profile.
   Review concrete changes and bundle material authority decisions once.
2. Implement and test the smallest real Rust-owned PostgreSQL transaction:
   native execution/typed attempt/Start/result, real ownership exclusion,
   unchanged Python-owned positives and exact native ancestor unlink behavior.
3. Connect one unchanged selected Python workflow end to end. Rust owns durable
   lifecycle/projection decisions; Python owns import, execution and unchanged
   public SDK behavior through the one closed credential implementation.
4. Qualify the same slice under mixed writers, concurrency, lost ACK, cancellation,
   duplicate/conflicting reports, source obligations and physical cleanup.
   Demonstrate rollback of new admissions without in-flight owner transfer,
   automatic replay or data repair.
5. Extend actual Rust ownership to the selected unchanged agent: typed agent
   attempts, real Python agent/model runtime, full existing tools/schema,
   idempotent child workflow intent/outcome, ordered steps, summary/usage/events
   and cancellation. No simulated terminal result may replace this acceptance.
6. Audit the full MVP and issue a concrete CONTINUE or STOP recommendation with
   reproducible parity, routing, observability and resource/cost evidence.

## Non-negotiable boundaries

Preserve API/SDK methods, status/error precedence, org/device/tenant authority,
source/deployment pins, typed attempt semantics, PostgreSQL leases/fences,
no-effect recovery conditions and no replay after possible effects. Use one
common schema/issuer family, not parallel prototype tables. Alembic remains
sole migration history; do not rewrite landed migrations. Runtime children get
no lifecycle database credentials. Preserve dedicated credential audience and
purpose, approved exact operations and non-upgrading renewal; redirects stay
disabled on credential-bearing internal HTTP calls.

Python retains workflow and agent/model execution, public SDK, existing
non-migrated control-plane services and dependency behavior. Do not introduce
PyO3 coupling, RabbitMQ, WinRM/PSRP, an SDK rewrite, generic delivery migration,
a general event/WebSocket/scheduler rewrite or Rust-specific workspace changes.
Sopdet remains independently blocked, not silently waived or replaced.

Use real supported images and identify interpreter, SDK, adapter, accepted source
and installed dependency environment. Do not call requirements text/counts a
runtime artifact or run tenant imports/install hooks during no-effect Prepare.
Do not undertake a universal packaging redesign to qualify one selected runtime.

No merge, production/release/deployment, live vendor/model use, wider capability
or held schema/role/policy change is authorized by this goal. Existing exhausted
campaigns stay stopped; do not reset limits through new names or workflows.
Escalate only material contract, authority, schema-ownership, recovery/ambiguity,
retention, scope or required human-control changes. Prepare a concrete reviewed
proposal first and continue independent permitted work while awaiting a decision.

## Operating loop

Each cycle inspect authoritative state, choose the earliest unproved milestone,
execute a bounded package, review its integration, verify it and update the one
acceptance table with exact source and evidence. Count progress as working code,
meaningful positive/negative test evidence, a settled blocking interface or a
new diagnosis that changes the next action. More specifications, duplicated
harnesses and status-only turns do not count as product progress.

Prefer the existing implementation and test lanes. Do not create another
supervisor/framework/conductor unless a concrete contract cannot be met with
what exists. Every package specifies owned paths, interfaces, non-goals,
acceptance commands and stop/report conditions before implementation.

After two cycles on the same blocker without new evidence, change the approach
or report the exact decision required; never weaken expectations or quietly
shrink the objective. Respect bounded repair/retry controls. Wait only on a
verified live handle and keep independent work moving. Close completed watches.

The Go workstream stays independent. No routine check-ins or acknowledgement
loops; communicate only about a concrete blocking seam/dependency. Do not edit
its accepted proof or repeat its experiment. Sol review/delegation follows the
current applicable authorization; one architect remains accountable.

## Evidence and completion

Run the same scenarios against pinned Python and candidate Rust. Compare public
responses/errors/auth/org rules and committed DB/attempt/fence/log/usage/event/
resource effects. Demonstrate deliberate response, DB and committed-event drift
detection. Normalize only explicit nondeterminism; never edit the oracle to pass.
Use the supported Linux Docker/CI lane, actual fmt/strict Clippy/Cargo tests,
Python quality/scoped integration tests and final literal pre-PR/normal CI.
Retain original failures, source/run/artifact identities and honest custody limits.

Success requires actual workflow AND selected agent ownership, unchanged public
consumers, safe same-database writers, preserved authority and ambiguity rules,
trusted stop/resource/source closure, tested reversible routing, observability
and healthy applicable checks. A critical unproved requirement prevents success.
Do not declare completion from a smaller, easier compatible demonstration.

If the strategy is falsified, produce a concrete STOP recommendation with the
failed requirement, decisive evidence, narrower useful Rust role, components to
keep/retire and rollback disposition. If CONTINUE, state the validated
assumptions, remaining Python ownership, next subsystem and introduced debt.
Do not conclude merely that Rust is promising. Keep this accepted objective intact while pursuing its milestones; do not
shrink success to the code or tests already completed.
