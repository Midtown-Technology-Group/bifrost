## Exact structural diff recommendation

A. Replace owner.execution_id RESTRICT FK with two distinct identities: immutable execution_identity UUID UNIQUE NOT NULL (historical identity), and nullable live_execution_id UUID UNIQUE referencing executions(id) ON DELETE SET NULL, CHECK live_execution_id IS NULL OR live_execution_id=execution_identity. All lifecycle guards resolve live rows by identity. This keeps a minimal nonsecret admission fence after native deletion without blocking its existing FK action. Add a narrow trusted native-delete linkage-detach path; allow only live_execution_id nonnull -> null, never reattach/reparent. owner assignment/request IDs and request digest remain immutable. Retaining full caller/source bytes forever is NOT implied: split sensitive evidence into separately managed payload storage with an approved deletion/redaction policy. Until such payload disposal rules are approved, do not claim deletion-complete compliance or apply persistent snapshots to production.

B. Analogously sessions retain immutable execution_identity, attempt_identity and assignment_id; use nullable live_attempt_id/live_execution_id for native composite FK association. CHECKs bind live values to immutable identity. FK must clear the linked pair together; do not use a composite SET NULL that accidentally nulls immutable assignment identity. Prefer nullable live_attempt_id FK plus native binding validated atomically at insertion and a separate composite live linkage table (session_id, execution_id, attempt_id) with typed pair FK ON DELETE CASCADE. That table may be removed by native deletion; immutable session evidence stays. No direct foreign pointer to deleted native attempt is needed in the tombstone. Review exact constraint SQL after choosing this branch; the original RESTRICT composite FK is not apply-ready.

C. Session close is monotonic rather than whole-row immutable: add closed_at and close_receipt_id set exactly once by CloseSession under the typed attempt fence, with a same-owner/session/type receipt association. Replace UNIQUE(attempt_id) with partial UNIQUE(attempt_identity) WHERE closed_at IS NULL. Admission of replacement additionally checks no committed or possible Start anywhere in that attempt lineage, not merely this partial index. Start receipt carries attempt_identity with unique committed start per typed attempt; report checks exact session/start. Session opening and closing are separate typed operations, never arbitrary coordinator UPDATEs. Existing native attempt constraint still enforces one active typed attempt per execution.

D. Delete-vs-live-session serialization: native execution deletion must run a narrowly approved delete guard under the same owner/attempt/source gate, deny deletion while an undrained Rust session/source obligation exists, or route through cancel/close/trusted reap before completing deletion. Because no current public native Execution delete path was found, do not introduce a new asynchronous public delete contract. Enumerate installed/admin retention before rollout; if it requires immediate delete of active work, STOP for that exact behavior decision. Once drained, native deletion may proceed with evidence link detachment and existing attempt/log/usage cascades, while minimum immutable identity/digest tombstones remain. No new blanket retention interval is proposed. Tombstone expiry remains disabled pending explicit safe replay horizon/source policy, not a claimed public data retention policy.
